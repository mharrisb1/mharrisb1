# FastAPI unified routing

For [Definite](https://definite.app), we have a few ways to interact with the backend:

1. [`/vX/` ] The main, client API
2. [`/api/`] The API used with the SDK and other programmable access
3. [`/mcp/`] Now our MCP server for agents

At first, the API and MCP endpoints were just added as an after thought to test product-market fit on new features, but as we validated that we wanted to keep moving in this direction a major problem popped up. The endpoints were mostly the same in terms of business logic but only differed in a few ways such as authentication, route paths, etc. that wraps the business logic. The immediate solution is to just abstract the business logic into controllers and then have each separate route use that API. That worked but I didn't like the boilerplate where we had 3 different routes that all look the exact same except for the path and authentication dependencies.

Now, I'm exploring ways to automatically handle this without much work from the dev to write that boilerplate. This so far has led to successes in reducing the amount of route arguments and automatic determination of the response models as well as the ability to define one handler to be used for multiple routes.

It's still not polished and ready to be showcased but there is a there there.
