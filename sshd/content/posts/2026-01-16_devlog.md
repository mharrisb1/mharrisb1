# Execution graphs with NetworkX

For part of our [docs](https://docs.definite.app/analyze-build/docs) pipeline execution, we have a simple `dependsOn` specification where you can say dataset A `dependsOn` dataset B so that if you have something like a SQL transformation pipeline where A creates a table and then B reads from table, that you can ensure that dependencies will be ran.

Under the hood, we are making use of [NetworkX](https://networkx.org) to build a `DiGraph`:

```py
nodes = list(mapping.keys())
edges: list[tuple[str, str]] = []
for key, value in mapping.items():
    if parents := cast(list[str] | None, value.spec.get("dependsOn"):
        edges.extend((parent, key) for parent in parents)

G = nx.DiGraph()
G.add_nodes_from(nodes)
if edges:
    G.add_edges_from(edges)
```

Then we are using [`topological_generations`](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.dag.topological_generations.html) to determine all of the parallelizable layers of the graph and execute those one at a time:

```py
for ix, layer in enumerate(nx.topological_generations(G)):
    ...
```

Quick demo from Google AI overviews:

```py
import networkx as nx

# Create a Directed Acyclic Graph (DAG)
DG = nx.DiGraph([(1, 2), (2, 4), (3, 4), (4, 5), (4, 6), (6, 7)])

# Get the topological generations
generations = nx.topological_generations(DG)

# Convert the iterator to a list for viewing and sort the nodes within each generation for consistent output
generations_list = [sorted(generation) for generation in generations]

print(generations_list)
# Output: [[1, 3], [2], [4], [5, 6], [7]]
```

# Finite state machine for sheets A1 notation

Part of the refactor for [duckdb_gsheets](https://github.com/evidence-dev/duckdb_gsheets) involves enhancing support for [A1 Notation Ranges](https://developers.google.com/workspace/sheets/api/guides/concepts#a1-notation). Previously, a complicated regex patter was used to check if a given string is a valid A1 range:

https://github.com/evidence-dev/duckdb_gsheets/blob/a0ee3ae7efe2c5ee9608b7dc7947ff40c948c4b1/src/gsheets_read.cpp#L42

```cpp
bool IsValidA1Range(const std::string &range) {
	// Matches things like A1, $A$1, A1:B2, $A1:$B2, etc.
	static const std::regex pattern("^\\$?[A-Za-z]+\\$?[0-9]+(:\\$?[A-Za-z]+\\$?[0-9]+)?$");
	return std::regex_match(range, pattern);
}
```

# Finished up first pass of C++ Google Sheets client for DuckDB extension

PR: https://github.com/evidence-dev/duckdb_gsheets/pull/100

A big part of the refactor is having a decent Google Sheets client API. First pass is looking pretty good. Here are some usage examples:

```cpp
#include "sheets/client.hpp"
#include "sheets/auth/bearer_token_auth.hpp"
#include "sheets/transport/httplib_client.hpp"

// Setup
HttpLibClient http;
BearerTokenAuth auth("your-access-token");
GoogleSheetsClient client(http, auth);

// Read values from a range
auto values = client.Spreadsheets("spreadsheet_id")
                    .Values()
                    .Get(A1Range("Sheet1!A1:D10"));

for (const auto &row : values.values) {
    for (const auto &cell : row) {
        std::cout << cell << "\t";
    }
    std::cout << std::endl;
}

// Update values
ValueRange newData;
newData.values = {{"Hello", "World"}, {"Foo", "Bar"}};
client.Spreadsheets("spreadsheet_id")
      .Values()
      .Update(A1Range("Sheet1!A1"), newData);

// Append rows
client.Spreadsheets("spreadsheet_id")
      .Values()
      .Append(A1Range("Sheet1!A1"), newData);

// Clear a range
client.Spreadsheets("spreadsheet_id")
      .Values()
      .Clear(A1Range("Sheet1!A1:D10"));

// Get spreadsheet metadata
auto metadata = client.Spreadsheets("spreadsheet_id").Get();
std::cout << "Title: " << metadata.properties.title << std::endl;
std::cout << "Sheets: " << metadata.sheets.size() << std::endl;

// Find a specific sheet
auto sheet = client.Spreadsheets("spreadsheet_id").GetSheetByName("Data");
std::cout << "Sheet ID: " << sheet.properties.sheetId << std::endl;
```
